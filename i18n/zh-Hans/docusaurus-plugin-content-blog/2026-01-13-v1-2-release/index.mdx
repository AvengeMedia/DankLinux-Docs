### 原生剪贴板和历史 {#native-clipboard-and-history}

<figure style={{ textAlign: 'center' }}>
  <ThemedImage

完整的零依赖剪贴板和剪贴板历史集成。
- 不依赖 cliphist 或 wl-clipboard 等外部工具。
- 可配置的最大条目大小、保留时长和自动清理。
- 带分页、按文本、图像或任何 mime 类型过滤的搜索 API 和 CLI。
- 自动忽略来自密码管理器（如 KeepassXC 和 1Password）的数据。防止敏感数据被存储到剪贴板历史。
- 导出和导入功能
- 用于从 cliphist 迁移历史的工具。

- **光标** - 从可用光标主题中选择、调整大小，并配置合成器特定的隐藏行为（键入时隐藏、触摸时隐藏、非活动超时）

### （破坏性）主题更新 {#breaking-theme-updates}

Ghostty 和 VSCode 主题已更改，不手动干预将停止工作。

<details>
<summary>Ghostty 和 VS Code 主题变更</summary>

**Ghostty**

主题路径已更改为 `~/.config/ghostty/themes/danktheme`。更新您的 Ghostty 配置：

```toml
# ~/.config/ghostty/config
# Add this
theme = dankcolors

# ! Remove this
# config-file = ./config-dankcolors
```

**VS Code / Codium**

由于内部变更，需要重新安装主题扩展：

1. 卸载当前的 "Dank material shell theme" 扩展
2. 从扩展市场重新安装：搜索 "DankLinux" 的 "Dank material shell theme"
3. Ctrl+Shift+P -> "Preferences: Color Theme" -> 选择 "Dynamic Base16 DankShell"
4. 触发主题重新生成 - 在 DMS 设置中更改主题或重启 DMS
5. 完全退出并重启 VSCode

</details>

### 剪贴板历史迁移 {#clipboard-history-migration}

建议按步骤移除现有的剪贴板历史守护进程，并将现有历史迁移到新的 DMS 剪贴板系统。

<details>
<summary>清理和迁移步骤</summary>

**1. 清理旧的剪贴板历史集成：**

从合成器配置中删除 `wl-paste --watch cliphist store` 守护进程/启动项。

```js
// ~/.config/niri/config.kdl
spawn-at-startup "wl-paste --watch cliphist store" // REMOVE THIS LINE
```

```toml
# ~/.config/hypr/hyprland.conf
exec-once = wl-paste --watch cliphist store # REMOVE THIS LINE
```

**2. 配置 DMS 剪贴板设置（可选）：**

迁移前，您可能需要在 DMS 设置 -> 系统 -> 剪贴板中配置保留设置。您可以配置最大条目大小、总条目数和保留时长。仅在您想覆盖默认值时需要。


**3. 将剪贴板历史从 `cliphist` 迁移到 DMS：**

剪贴板历史不会从以前的版本自动迁移。您仍然可以使用 `cliphist` CLI 访问它。新的剪贴板历史位于 `~/.cache/DankMaterialShell/clipboard/db`——这是一个 [bbolt](https://github.com/etcd-io/bbolt) 数据库。

要迁移旧历史：

```bash
# First stop DMS
systemctl --user stop dms # Or dms kill, if not using systemd
# Run migration (optionally override path with cliphist-migrate /path/to/db)
dms cl cliphist-migrate
# Start DMS again
systemctl --user start dms # or dms run -d, if not using systemd
```

然后您可以卸载 cliphist 并删除位于 `~/.cache/cliphist/db` 的旧数据库

`wl-clipboard` 也可以移除，不过保留它对依赖它的插件或脚本很有用。

```bash
# DMS clipboard CLI 与 wl-clipboard 功能对等
# To copy text:
echo "Hello, World!" | dms cl copy
# To paste text:
dms cl paste
```

</details>

### 合成器配置更新 {#compositor-configuration-updates}

对于 niri 或 Hyprland，您可以运行 `dms setup` 生成新的合成器配置——显示器配置将被保留，原始配置将被备份。主要变更迁移到更模块化的配置。

仅当您希望使用 DMS 设置中新的光标、输出、布局和按键绑定控制时才需要更改。

<details>
<summary>niri</summary>

使用 GUI 光标和输出设置时必需。

1. 创建新文件

```bash
mkdir -p ~/.config/niri/dms
touch ~/.config/niri/dms/cursor.kdl
touch ~/.config/niri/dms/outputs.kdl
```

2. 将现有配置移到新文件

```js
// ~/.config/niri/dms/cursor.kdl
// Move cursor {} block from config.kdl
cursor {
    xcursor-theme "Bibata-Original-Ice"
    xcursor-size 24
}

// ~/.config/niri/dms/outputs.kdl
// Move output {} blocks from config.kdl
output "DP-1" {
    position 0 0
    scale 1.0
    transform normal
}
```

3. 在配置中包含新文件

```js
// ~/.config/niri/config.kdl
// Recommended to place at the end of the file
include "dms/cursor.kdl"
include "dms/outputs.kdl"
include "dms/layout.kdl"
```

</details>

<details>
<summary>Hyprland</summary>

使用 GUI 光标、输出、布局和按键绑定设置时必需。

1. 创建新文件

```bash
mkdir -p ~/.config/hypr/dms
touch ~/.config/hypr/dms/cursor.conf
touch ~/.config/hypr/dms/outputs.conf
touch ~/.config/hypr/dms/layout.conf
touch ~/.config/hypr/dms/binds.conf
```

2. 将现有配置移到新文件

```bash
# ~/.config/hypr/dms/cursor.conf
# Move cursor settings from hyprland.conf
env = HYPRCURSOR_THEME,Bibata-Original-Ice
env = HYPRCURSOR_SIZE,24
env = XCURSOR_THEME,Bibata-Original-Ice
env = XCURSOR_SIZE,24

# ~/.config/hypr/dms/outputs.conf
# Move monitor lines from hyprland.conf
monitor = DP-1,2560x1440@144,0x0,1

# ~/.config/hypr/dms/layout.conf
# Move general layout settings from hyprland.conf
general {
    gaps_in = 5
    gaps_out = 10
    border_size = 2
}

# ! Binds do not need to be moved, only edited/new binds via GUI will be stored here
```

```bash
# ~/.config/hypr/hyprland.conf
```
```bash
# Recommended to place at the end of the file
source = ./dms/cursor.conf
source = ./dms/outputs.conf
source = ./dms/layout.conf
source = ./dms/binds.conf
```

</details>

### NixOS 更新 {#nixos-updates}

DMS 1.2 为 NixOS 集成和基于 flake 的安装体验带来重大改进：

**Home Manager 模块增强**
- 用于声明式剪贴板配置的新 `clipboardSettings` 选项
- 插件现在可以直接在其配置中包含逐插件设置
- 移除 `default*` 设置选项，改为能够设置实际的设置文件
- 通过 home-manager 模块改进插件安装和管理

**NixOS 模块改进**
- 在 NixOS 模块中添加插件支持，支持声明式安装
- 默认启用 `power-profiles-daemon` 和 `accounts-daemon`，以获得更好的电源管理和用户账户集成
- QML 依赖项现在正确包含在 `dms-shell` 软件包中

**niri 集成**
- 添加对 niri-flake 的配置包含支持。DMS 生成的配置文件现在可与 niri 基于flake 的设置无缝协作

**插件注册表 Flake**
- 新的 [dms-plugin-registry](https://github.com/AvengeMedia/dms-plugin-registry) Nix flake 将所有社区插件作为软件包提供
- 插件每天从注册表自动更新
- 简单的声明式安装——只需按 ID 启用插件
- 同时适用于 NixOS 和 Home Manager 模块

:::note
DMS Flake 选项名称现已从 `programs.dankMaterialShell` 更改为 `programs.dank-material-shell`。模块名称也已更改。
旧模块名称仍可使用，但您会收到有关新名称的弃用警告。
:::

:::info
[nixpkgs 模块](/docs/dankmaterialshell/nixos) 的文档将在 DMS 1.2 进入 `nixos-unstable` 后立即更新。
:::

请查阅[文档](/docs/dankmaterialshell/nixos-flake)了解如何使用新功能配置 DMS 1.2 的更多信息。
