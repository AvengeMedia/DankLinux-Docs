本指南涵盖了跨不同 Linux 发行版安装 DankMaterialShell 的方法和方法。

## 依赖关系 {#dependencies}

- [**quickshell**](https://github.com/quickshell-mirror/quickshell) (必填) - 核心框架
- [**cava**](https://github.com/karlstav/cava)（可选）- 音频可视化工具小部件
- [**dankcalendar**](https://github.com/AvengeMedia/dankcalendar)（可选）- 完整的桌面日历应用程序，具有 DMS 日历小部件的本机集成
- [**dgop**](https://github.com/AvengeMedia/dgop)（可选）-资源小部件的系统遥测
- [**dsearch**](https://github.com/AvengeMedia/danksearch)（可选）- 文件系统搜索引擎
- [**matugen**](https://github.com/InioX/matugen)（可选）- Material Design 调色板生成
- [**niri**](https://github.com/niri-wm/niri)（可选）- DMS 团队选择的 Wayland 合成器
- [**qt6-multimedia**](https://github.com/qt/qtmultimedia)（可选）- 系统声音反馈

有关 Fedora、Debian、Ubuntu 和 OpenSUSE 上预构建的软件包，请参阅 [DankLinux 存储库](../danklinux) 页面。

:::note

仅需要**Quickshell**。所有其他依赖项都是可选的并启用特定功能。

:::

## Arch Linux 及其衍生版 {#arch--derivatives}

`dms` 可在官方 Arch 存储库（额外）中找到，并作为 AUR 中的开发包。

</TabItem>
<TabItem value="git" label="Latest Development Build">

</TabItem>

## Fedora 和 CentOS {#fedora--centos}

DankMaterialShell 可通过 Fedora 43/44、Rawhide 和 CentOS 10 的 COPR 存储库获得。

</TabItem>

## Debian 和 Ubuntu {#debian--ubuntu}

DankMaterialShell 可通过 Debian 的 Open Build Service (OBS) 和 Ubuntu 的 Launchpad PPA 获得。

### Debian {#debian}

软件包已发布在 OBS 上，用于 **Debian 13 (Trixie)**、**Debian 测试** 和 **Debian Sid**。

稳定的 **quickshell** 应该来自 Debian（请参阅 [DankLinux Debian 部分](../danklinux#debian)）。适用于 Debian 的 DankLinux OBS `quickshell` 软件包已**弃用** — 如果您仍然拥有它，请先安装 `sudo apt remove quickshell`，然后再继续。

选择您的版本，然后选择稳定包或开发包。

DankMaterialShell 可通过 GURU 覆盖在 Gentoo 上使用。

启用官方 [GURU](https://wiki.gentoo.org/wiki/Project:GURU) 覆盖，该覆盖将 DMS (`gui-apps/dankmaterialshell`) 与配套工具 `gui-apps/dgop` 和 `gui-apps/danksearch` 一起打包。

```bash
sudo eselect repository enable guru
sudo emaint sync -r guru
```

### 从 TTY 运行 Wayland（没有显示管理器） {#running-wayland-from-tty-without-a-display-manager}

:::tip

如果您使用**`dms-greeter`**，所有席位管理、D-Bus 初始化和运行时目录都会自动为您处理。如果您选择完全绕过显示管理器并从纯 TTY shell 手动启动合成器，则只需执行以下手动步骤。

:::

如果您选择直接从 TTY 登录提示符启动合成器（如 `niri`、`Hyprland` 或 `sway`）而不是使用显示管理器（如 `greetd`），则 Void Linux 需要一些手动运行时配置，因为它默认情况下不运行 systemd：

#### 1.配置席位管理（`elogind`） {#1-configure-seat-management-elogind}
Wayland 合成器需要直接访问输入和图形硬件设备的权限。 `dms` 包已经依赖于 `dbus` 和 `elogind`；启用他们的服务：

```bash
sudo ln -s /etc/sv/dbus /var/service/
sudo ln -s /etc/sv/elogind /var/service/
```
*注意：注销 TTY 并重新登录（或重新启动），以便您的登录获得 elogind 会话，该会话授予席位访问权限并设置 `XDG_RUNTIME_DIR`。如果您更喜欢 `seatd`，请启用它并将您的用户添加到 `_seatd` 组，但不要同时运行两个席位管理器。*

#### 2. 启动会话 {#2-launch-the-session}
桌面实用程序（包括 DMS 守护程序和面板）需要 D-Bus 会话总线进行通信。启动包含在 D-Bus 会话中的合成器：

```bash
dbus-run-session niri
# or
dbus-run-session Hyprland
```

#### 3.手柄`XDG_RUNTIME_DIR` {#3-handle-xdgruntimedir}
Wayland 套接字和配置需要定义 `XDG_RUNTIME_DIR`。如果它没有在您的系统上自动设置（例如，如果您没有运行 `elogind`），请将以下后备脚本添加到您的 shell 登录配置文件（例如，`~/.bash_profile` 或 `~/.zprofile`）：

```bash
if [ -z "$XDG_RUNTIME_DIR" ]; then
    export XDG_RUNTIME_DIR=/run/user/$(id -u)
    if [ ! -d "$XDG_RUNTIME_DIR" ]; then
        mkdir -p "$XDG_RUNTIME_DIR"
        chmod 700 "$XDG_RUNTIME_DIR"
    fi
fi
```

### Systemd 集成（推荐） {#systemd-integration-recommended}

:::tip[DankInstall 用户]

如果您使用 [dankinstall](../dankinstall)，则已配置。安装程序在安装过程中运行 `systemctl --user enable --now dms`。

:::

**启用自动启动：**

```bash
systemctl --user enable dms
```

**手动控制：**

```bash
# Start DMS now
systemctl --user start dms

# Check status
systemctl --user status dms

# View logs
journalctl --user -u dms -f

# Restart DMS
systemctl --user restart dms

# Disable autostart
systemctl --user disable dms
```

:::warning

如果使用 systemd 自动启动，请从合成器的配置中删除 `dms run` / `spawn "dms" "run"` / `exec-once=dms run` 以避免运行 DMS 两次。

:::

### 特定于合成器的 Systemd 设置 {#compositor-specific-systemd-setup}

不同的合成器具有不同级别的 systemd 会话集成。选择与您的合成器匹配的部分。

:::tip[为什么要使用add-wants？]

如果您安装了多个桌面环境（例如 Plasma、GNOME、niri），则使用 `systemctl --user enable dms` 在*所有*环境中启动 DMS。使用 `add-wants` 将 DMS 绑定到特定合成器的服务或会话目标，因此它仅在您想要的位置运行。当您登录 Plasma 或 GNOME 时，DMS 将不会启动。

:::

#### 尼里 {#niri}

niri 具有本机 systemd 会话集成。将DMS绑定到niri的服务：

```bash
systemctl --user add-wants niri.service dms
```

DMS 在 niri 启动时启动，在 niri 退出时停止。它不会在其他会话中运行。

#### 海普兰 {#hyprland}

默认情况下，Hyprland 不会初始化 systemd 用户会话。您需要将环境导出到 systemd 才能使用户服务正常工作。

创建会话目标：

```ini title="~/.config/systemd/user/hyprland-session.target"
[Unit]
Description=Hyprland Session Target
Requires=graphical-session.target
After=graphical-session.target
```

添加到您的 Hyprland 配置（在任何 `env =` 行之后）：

```lua title="~/.config/hypr/hyprland.lua"
hl.on("hyprland.start", function()
  hl.exec_cmd("dbus-update-activation-environment --systemd --all")
  hl.exec_cmd("systemctl --user start hyprland-session.target")
end)
```

将 DMS 绑定到会话目标：

```bash
systemctl --user add-wants hyprland-session.target dms
```

#### 芒果WC {#mangowc}

[MangoWC](https://github.com/DreamMaoMao/mangowc)是一个基于dwl(wlroots)的动态平铺合成器。与其他 wlroots 合成器一样，它需要手动导出 systemd 用户服务的环境。

创建会话目标：

```ini title="~/.config/systemd/user/mango-session.target"
[Unit]
Description=MangoWC Session Target
Requires=graphical-session.target
After=graphical-session.target
```

添加到您的 MangoWC 配置：

```conf title="~/.config/mango/config.conf"
exec-once=dbus-update-activation-environment --systemd --all
exec-once=systemctl --user start mango-session.target
```

将 DMS 绑定到会话：

```bash
systemctl --user add-wants mango-session.target dms
```

#### 摇摆 {#sway}

Sway（基于 wlroots）需要为 systemd 服务导出环境。

创建会话目标：

```ini title="~/.config/systemd/user/sway-session.target"
[Unit]
Description=Sway Session Target
Requires=graphical-session.target
After=graphical-session.target
```

添加到您的 Sway 配置：

```conf title="~/.config/sway/config"
exec dbus-update-activation-environment --systemd --all
exec systemctl --user start sway-session.target
```

将 DMS 绑定到会话：

```bash
systemctl --user add-wants sway-session.target dms
```

#### 奇迹WM {#miracle-wm}

[Miracle WM](https://github.com/miracle-wm-org/miracle-wm) 是一个基于 Mir 构建的平铺 Wayland 合成器。与其他没有本机 systemd 会话集成的合成器一样，它需要手动导出环境。

创建会话目标：

```ini title="~/.config/systemd/user/miracle-wm-session.target"
[Unit]
Description=Miracle WM Session Target
Requires=graphical-session.target
After=graphical-session.target
```

将 DMS 绑定到会话：

```bash
systemctl --user add-wants miracle-wm-session.target dms
```
