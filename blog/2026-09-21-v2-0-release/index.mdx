**DankMaterialShell is now Dux Shell**, and Dank Linux is now **Dux Labs**.

DMS 2.0 "Heisenberg" is here with a new design across the shell, plugins for Dash and OmegaDock, the new Dux Dot, and much deeper compositor support for Hyprland, MangoWC, and newly added, Aqueous. There's a customizable lock screen, the Dux Lyrical Engine, and **Dux Files**, a new standalone file manager.

## DankMaterialShell is now Dux Shell

DMS started as one shell. Since then it has picked up a greeter, a system monitor, a search service, a calendar, a package repository, and a plugin community, and 2.0 adds a file manager. That's a lot to keep calling DankMaterialShell, so the whole suite is moving under one name: **Dux Labs**.

| Before | Now |
|---|---|
| Dank Linux | Dux Labs |
| DankMaterialShell | Dux Shell |
| DankGreeter | Dux Greeter |
| DankSearch | Dux Search |
| DankGOP | Dux GOP |
| DankCalendar | Dux Calendar |
| DankLinux repository | Dux Labs repository |
| new | Dux Files |

It's the same team and the same projects. The shell is still DMS, and the command is still `dms`.

### Why "Dux"?

**Dux** is our mascot, and the name is a nod to **Tux**, the Linux penguin. It's short, it's not taken by any major software projects, it starts with a D so we don't have to rename the binaries (`dms`, `dcal`, `dgop`), and it gives a friendlier vibe than "Dank" did.

The new GitHub org is [duxlabs-dev](https://github.com/duxlabs-dev). The package repositories move shortly after launch. Details are in [the repositories](#the-repositories) section at the end.

## Dux Files

**Dux Files** is a new file manager from Dux Labs, shipping alongside 2.0. It's a standalone app: a small Go daemon does the file work and a Quickshell window sits on top. It shares the look of the shell and follows your DMS theme when both run, but it doesn't need DMS.

<figure className={styles.screenshot}>
  <ThemedImage alt="Dux Files in grid view with the preview drawer open on a picture" sources={{light: useBaseUrl('/img/dfileslight.png'), dark: useBaseUrl('/img/dfiles.png')}} />
  <figcaption>Dux Files in grid view with the preview drawer.</figcaption>
</figure>

- **Tabs and split view:** open folders in tabs, or show two folders side by side and drag files between them.
- **List, grid, and column views:** each folder remembers its sort order and list or grid view. Column view stays on as you browse.
- **Preview:** press Space to see a preview and details of the selected file next to the list.
- **File operations:** copy, move, rename, and delete with progress and undo. If you don't have permission, retry as administrator.
- **Archives:** open zip, tar, 7z, and rar files, and compress files into zip or tar, without installing extra tools.
- **Search:** search the current folder or your whole home, filtered by type, date, or size.
- **Drives and network shares:** mount USB drives, unlock encrypted ones, and connect to SFTP, SMB, and WebDAV servers.
- **Works with your apps:** "Show in folder" from your browser opens Dux Files. It can also replace the open and save dialogs in other apps.
- **Keyboard navigation:** drive the entire interface with the keyboard only.

Get it from the [installation guide](/docs/dfiles/installation), and read the rest in the [Dux Files docs](/docs/dfiles).

## Dock

The dock can be used as an OmegaDock now. Add more than one, put each on any edge, and choose a compact icon row or a taskbar.

Taskbar mode is new. The dock spans the whole edge, end to end. Compact mode is still a strip of icons.

The dock runs the same widgets as the bar, including plugins, so a clock, tray, media, workspaces, or anything a plugin provides can sit next to your apps. A widget can open as a popout or inline, where the dock grows and the panel sits beside the icons. Plugin authors provide that panel with `attachedContent`. See [widgets in a dock](/docs/dms/plugin-development#widgets-in-a-dock).

Hover magnification scales the icon under the pointer and can push its neighbors aside, and the focused app can expand into a pill. The dock animates on the same spring as the island and the bars.

## niri

niri can turn the touchpad on and off. DMS shows the change on screen, and the default config binds the touchpad key to `toggle-touchpad`. Focus follows mouse works too.

Switching workspaces can show an on-screen display, window rules can set a column's width and height as a percentage, and connected displays can be cycled. A hidden bar gets out of the way while the overview is open, and a dock set to overview-only shows up there.

## Hyprland and MangoWC

**Hyprland** catches up with 0.56: dwindle, master, and scrolling layouts with their own settings, special workspaces as scratchpads, and the new blur styles, glow, motion blur, and group tabs. Wobbly windows work on Hyprland git.

**MangoWC** 0.18 renamed its config keys to snake_case. DMS writes the new format, and `dms config mango-migrate` converts an existing config.

On both, mouse, touchpad, keyboard, and focus follows mouse are in Settings, and `dms setup` can start the shell from `hyprland-session.target` or `mango-session.target`.

## More in 2.0

- **Launcher:** dmenu mode, custom keybinds, app editing, VPN search, Open with for files, Flatpak uninstall, an option to focus a running window instead of launching a new one, and an option to turn off history.

- **Multiplexers:** Herdr joins tmux and zellij.

- **Desktop widgets:** editor improvements.
- **Notifications:** extra rule conditions, timed per-app mutes, hovered popups stay put, and `invokeLast` over IPC.
- **Screenshots:** snap to open popouts and Ctrl+C to copy without saving.
- **Displays:** per-output ICC color profiles and color temperature.
- **System updates:** floating window, Portage backend, highlighted upgrade logs, and a reboot prompt after kernel updates.
- **Channels:** `dms switch beta` moves to beta packages after taking a backup, and `dms switch stable` goes back. Name a package to switch only that one. See [Switch channels](/docs/dms/cli-switch).
- **Distros:** official PikaOS support, Enterprise Linux 10 (RHEL, CentOS Stream, Rocky Linux, AlmaLinux), and native FreeBSD support.

## Upgrade Notes

### (Breaking) App ID Change

The DMS app ID is now `dev.duxlabs.shell`, replacing `com.danklinux.dms`. The window rules DMS manages itself are updated automatically. If you wrote your own compositor window rules for DMS windows, update them to the new ID.

On niri, for example, this:

```kdl
window-rule {
    match app-id=r#"^com\.danklinux\.dms$"#
    open-floating true
}
```

becomes:

```kdl
window-rule {
    match app-id=r#"^dev\.duxlabs\.shell$"#
    open-floating true
}
```

## Plugin authors: update your widgets

:::warning[Deprecated widget imports and types]

The old widget wrappers are deprecated and will be removed in a future release. Update the imports **and** the type names. The compatibility wrappers log a warning with the replacement to use.

:::

For example, this:

```qml
import qs.Widgets

DankButton {
    text: "Open"
}
```

becomes:

```qml
import qs.DCommon.Widgets

DButton {
    text: "Open"
}
```

Some common replacements:

| Old type | New type in `qs.DCommon.Widgets` |
|---|---|
| `DankButton` | `DButton` |
| `DankActionButton` | `DActionButton` |
| `DankIcon` | `DIcon` |
| `DankSlider` | `DSlider` |
| `DankToggle` | `DToggle` |
| `DankTextField` | `DTextField` |
| `DankTabBar` | `DTabBar` |
| `DankFlickable` | `DFlickable` |
| `DankListView` | `DListView` |
| `DankScrollbar` | `DScrollbar` |

`StyledText` keeps its name and is also available from `qs.DCommon.Widgets`. Shell-specific types still live in `qs.Widgets`, so keep that import if your plugin uses them. Check the warning for each deprecated type rather than replacing every import blindly.

The replacements are in the [shared widget library](https://github.com/duxlabs-dev/dux-qml-common/tree/master/DCommon/Widgets), and the [compatibility wrappers](https://github.com/duxlabs-dev/dux-shell/tree/master/quickshell/Widgets) show the old and new names.

## Notes for Package Maintainers

DMS now lives at [duxlabs-dev/dux-shell](https://github.com/duxlabs-dev/dux-shell).

The desktop files and icon follow the new app ID, so update any install lines that name them:

| Old file | New file |
|---|---|
| `assets/com.danklinux.dms.desktop` | `assets/dev.duxlabs.shell.desktop` |
| `assets/com.danklinux.dms.notepad.desktop` | `assets/dev.duxlabs.shell.notepad.desktop` |
| `assets/com.danklinux.dms.svg` | `assets/dev.duxlabs.shell.svg` |

Dux Calendar's assets moved the same way, from `com.danklinux.dankcalendar.*` to `dev.duxlabs.calendar.*`.

Binary names, systemd units, and the `dms-open.desktop` URL handler are unchanged.

Renaming packages to the new names is not required, but we'd prefer it:

| Old name | New name |
|---|---|
| `dms`, `DankMaterialShell`, `dms-shell` | `dux-shell` |
| `dgop` | `dux-gop` |
| `dankcalendar`, `dank-calendar` | `dux-calendar` |
| `dank-greeter` | `dux-greeter` |

## The repositories

2.0 is the rebrand. The package repositories move next.

New Dux Labs repositories are almost ready to replace the AvengeMedia and DankLinux ones. Shortly after this release, 2.0.1 will move installs and updates onto them, including dankinstall. Existing users will run `dms migrate dux` to point their distro's repositories at Dux Labs. Until that ships, keep the repositories you already have.
