1.6 puts a lot of this cycle into making the shell and CLI faster and lighter - less waiting on the things you do all day, less memory and CPU the rest of the time:

- **IPC**: `dms ipc call` used to launch a whole quickshell process just to deliver one message. Now it talks to the shell directly, and the median call dropped from 49.8 ms to 9.6 ms. Every keybind and script that goes through dms gets this for free.
- **Screenshots**: saving is 4-8x faster. A full 1440p screen writes in 25 ms instead of 94 ms, JPEG in 29 ms instead of 75 ms, and re-capturing a saved region in 12 ms instead of 106 ms.
- **Region selector**: dragging a selection used to redraw the entire screen on every pointer move, so it couldn't keep up with the display. Now only the edges of the rectangle redraw, and drags feel instant at any refresh rate.
- **Color picker**: same story for the eyedropper - it stopped copying the whole screen every time the pointer moves, so it stays smooth on big and multi-monitor setups and stops burning CPU while you drag.
- **Memory**: the shell uses ~76 MB less memory (-19%) on a clean two-monitor setup, with no change in smoothness.

### vs other tools

dms, grim, and hyprpicker all grab the screen from the compositor the same way, so the differences below come down to what each tool does after that.

Screenshots vs grim:

| capture (PNG) | grim | dms 1.6 |
|---|---:|---:|
| one 1440p output | 114.7 ms | 23.5 ms (4.9x) |
| both outputs | 344.3 ms | 71.7 ms |
| 800x600 region | 26.0 ms | 12.1 ms |

grim writes its PNG on a single core; dms uses all of them, and still writes a 680 KB file where grim writes 11 MB.

Color picker vs hyprpicker: with the picker open and the pointer sitting still, hyprpicker keeps redrawing at ~59% of a CPU core on this setup; `dms color pick` sits at 0% and only redraws when the pointer actually moves.

<small>*Benchmarked 1.5.3 vs 1.6 with stock settings on one machine (Ryzen AI 9 HX 370, two 1440p displays). Absolute numbers will vary with hardware and config; Tool comparisons ran on the same machine against grim (current Arch) and hyprpicker v0.4.7; hyprpicker's idle CPU likely scales with refresh rate and output count.*</small>

## Dank Island

1.6 introduces Dank Island, a new bar instance built around a central island with satellite widgets.

- **Satellites**: background, transparency, and blur options, with bigger click targets
- **Live faces**: hover to expand, a notification counter, and notification severity rendered as a border accent
- **Spring physics**: a new motion system with spring-based physics and hybrid material animations. The island paces its transitions from the spring instead of fixed animation curves.

## Standalone Greeter

The greeter moved out of the shell into its own project, [dank-greeter](https://github.com/AvengeMedia/dank-greeter). It ships as a standalone package with its own release cycle instead of riding along inside DMS.

The split came with an auth rework: PAM management and settings in both the greeter and lock screen, relying on distro system auth instead of DMS-managed sessions, custom PAM policies, and U2F security keys on the lock screen.

## Unified Versioning

1.6 changes how the Dank Desktop is versioned: dsearch, dgop, dcal, and dgreeter are now versioned and released together with DMS. One version number covers the whole desktop.

## Fewer Dependencies

1.6 keeps shedding external dependencies:

- The quickshell configuration is now embedded in the DMS binary and mounted at runtime
- dgop is built in instead of a separate process
- curl dropped, bluetooth audio codec support built in
- Initial FreeBSD support landed along the way

## Notes for Package Maintainers

- The quickshell UI is embedded in the dms binary and mounted at runtime. Packages no longer install `/usr/share/quickshell/dms`, and XDG auto-discovery of `~/.config/quickshell/dms` is removed: `-c` or `DMS_SHELL_DIR` explicitly override the embedded config.
- Release binaries and all -git packages build with the embedded shell. Sockets, pidfiles, and env names are unchanged, and IPC stays wire-compatible (APIVersion 28). One behavior change: `ping` over the socket returns `{"pong":true}` instead of `"pong"`.
- The greeter is its own package now, [dank-greeter](https://github.com/AvengeMedia/dank-greeter), with its own release artifacts. `dms greeter install` expects the dms-greeter binary from that package.
- dgop and curl are no longer external dependencies.
- dsearch, dgop, dcal, and dgreeter tag and release together with DMS from this release on.

## Plugins

The plugin ecosystem got a full pass this cycle:

- **New grid-style plugin browser**, and runtime plugins are searchable from settings
- **Portable plugin lockfile** for reproducing a plugin set across machines
- **Multiple plugin and theme registries** via env vars
- **Plugin i18n**: plugins can ship their own translations through `I18n.trFor()`
- **Desktop widgets**: runtime resize API, symlinked config support

The [registry](https://plugins.danklinux.com) is past 330 plugins, 81 of them added this cycle. Two standouts:

- **[Quick Capture](https://github.com/hthienloc/dms-quick-capture)** by Loc Huynh: screen capture with drawing and annotation tools, plus OCR and QR decoding
- **[Dank Software Depot](https://github.com/vinceecniv/DankSoftwareDepot)** by Vincent Blok: a full software and updates center - update cards with release notes, an app store covering system repos, Flathub, and AppImage, installed-software management, and firmware updates. Fedora first, Debian/Ubuntu and Arch experimental.

## Screenshots & Capture

Beyond the encoder speedups above, capture itself got better:

- Drag a region across outputs, alt to restrict to one output, ctrl to drag the selection
- Native cursor shapes in the selector
- Initial scroll capture mode
- 10-bit color support via `wp_color_manager_v1`
- `--json` flag for capture metadata

## Everything Else

- **Network**: WiFi hotspot support, OWE networks, native Fortinet VPN auth
- **Bluetooth**: multi-adapter support
- **Settings**: diff-only configs with a machine-state split, plus a backup CLI
- **Power menu**: user-defined custom buttons
- **Battery**: optionally lower refresh rate on battery
- **Wallpaper**: folder-based selection and shuffle

## What's Next

1.6 is also a direction marker. DMS started as a shell, and the pieces around it - search, monitoring, calendar, greeter - have grown into a suite that now versions and releases as one. From here development shifts toward a full desktop environment paradigm: standalone apps that share the Dank design language and theming, on any compositor, instead of everything living inside the shell.

In development for upcoming releases:

- **Standalone file browser**: the file browser graduates from a shell surface into its own app
- **DankConnect**: phone integration for the Dank Desktop
- More shell built-ins splitting into standalone suite apps, the way the greeter did this cycle
