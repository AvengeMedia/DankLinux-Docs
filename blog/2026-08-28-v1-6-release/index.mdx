1.6 puts a lot of this cycle into making the shell and CLI faster and lighter - less waiting on the things you do all day, less memory and CPU the rest of the time:

- **IPC**: `dms ipc call` used to launch a whole quickshell process just to deliver one message. Now it talks to the shell directly, and the median call dropped from 49.8 ms to 9.6 ms. Every keybind and script that goes through dms gets this for free.
- **Screenshots**: saving is 4-8x faster. A full 1440p screen writes in 25 ms instead of 94 ms, JPEG in 29 ms instead of 75 ms, and re-capturing a saved region in 12 ms instead of 106 ms.
- **Region selector**: dragging a selection used to redraw the entire screen on every pointer move, so it couldn't keep up with the display. Now only the edges of the rectangle redraw, and drags feel instant at any refresh rate.
- **Color picker**: same story for the eyedropper - it stopped copying the whole screen every time the pointer moves, so it stays smooth on big and multi-monitor setups and stops burning CPU while you drag.
- **Memory**: the shell uses ~76 MB less memory (-19%) on a clean two-monitor setup, with no change in smoothness.

### vs other tools

dms, grim, and hyprpicker all grab the screen from the compositor the same way, so the differences below come down to what each tool does after that.

Screenshots vs grim:

| capture (PNG) | grim | dms 1.6 |
|---|---:|---:|
| one 1440p output | 114.7 ms | 23.5 ms (4.9x) |
| both outputs | 344.3 ms | 71.7 ms |
| 800x600 region | 26.0 ms | 12.1 ms |

grim writes its PNG on a single core; dms uses all of them, and still writes a 680 KB file where grim writes 11 MB.

Color picker vs hyprpicker: with the picker open and the pointer sitting still, hyprpicker keeps redrawing at ~59% of a CPU core on this setup; `dms color pick` sits at 0% and only redraws when the pointer actually moves.

<small>*Benchmarked 1.5.3 vs 1.6 with stock settings on one machine (Ryzen AI 9 HX 370, two 1440p displays). Absolute numbers will vary with hardware and config; Tool comparisons ran on the same machine against grim (current Arch) and hyprpicker v0.4.7; hyprpicker's idle CPU likely scales with refresh rate and output count.*</small>

## Dank Island

1.6 introduces Dank Island, a new bar instance built around a central island with satellite widgets.

- **Satellites**: areas for widgets on either side of the central island.
- **Live faces**: The face of the island reacts dynamically to user interactions and system events - such as notifications, media playback, and OSD triggers.
- **Spring physics**: the island paces its transitions from a spring instead of fixed animation curves.

<small>Enable the Island in Settings -> Primary Bar -> Island</small>

## Spring Motion

The island's motion system is not island-only. 1.6 swaps fixed animation curves for spring physics across the shell: popouts, modals, the dock, OSDs, notification popups, the workspace switcher, and both the niri and Hyprland overviews move on springs now.

Typography & Motion in settings was reorganized around it, with a bounce control for how much the spring overshoots and a reduce motion switch that takes it back out. Content that is already open still resizes on bezier curves; springs are for things arriving and leaving.

## Unified Versioning

1.6 changes how the Dank Desktop is versioned: dsearch, dgop, dcal, and dgreeter are now versioned and released together with DMS. One version number covers the whole desktop.

## Standalone Greeter

The greeter moved out of the shell into its own project, [dank-greeter](https://github.com/AvengeMedia/dank-greeter). It ships as a standalone package with its own release cycle instead of riding along inside DMS.

## Screenshots & Capture

Beyond the encoder speedups above, capture itself got better:

- Drag a region across outputs, alt to restrict to one output, ctrl to drag the selection
- Native cursor shapes in the selector
- Initial scroll capture mode
- 10-bit color/HDR support via `wp_color_manager_v1`
- `--json` flag for capture metadata

## Theming

- **GTK3 dynamic theming**: with adw-gtk3 installed, DMS copies the light and dark variants into `~/.local/share/themes` and patches the copies with your generated colors. GTK3 apps then follow the system color scheme and switch live, no restart. Without adw-gtk3 it falls back to the `dank-colors.css` import. A `gtk.css` or dconf `gtk-theme` you set yourself is no longer overwritten.
- **Qt**: qtengine works as a platform theme, and so does `QT_PLATFORMTHEME=kde`.
- **matugen**: smart mode and scheme type are configurable, dank16 emits the full matugen color format, and there are new templates for Fcitx5 and Vesktop.
- **Contrast**: the theme browser shows WCAG data with per-theme breakdowns, so you can see what a theme does to legibility before you apply it.
- Settings -> Theme Color has an Extract button that writes the live theme out as one dark and light JSON file.

## Network

- **WiFi hotspot**: share the machine's connection from the shell
- **Cellular**: modem support on the NetworkManager backend
- **OWE**: open networks with opportunistic wireless encryption connect, including transition mode
- **Fortinet**: password profiles authenticate inside DMS with `openconnect --authenticate` and hand the short-lived cookie to NetworkManager. An untrusted server certificate shows its fingerprint for confirmation, and the fingerprint is only saved once the tunnel actually connects
- **802.1x**: EAP method selection, and credential persistence works again

## Config & Backup

settings.json and session.json only store what differs from the defaults now, so your config is the diff and not a dump of every value DMS knows about. Machine-specific state moved out of settings.json into session.json, which makes the settings half portable between machines.

`dms backup create` writes a tar.gz of `~/.config/DankMaterialShell`, and `dms backup restore <archive>` puts it back.

## Fewer Dependencies

1.6 keeps shedding external dependencies:

- The quickshell configuration is now embedded in the DMS binary and mounted at runtime
- dgop is built in instead of a separate process
- curl dropped, bluetooth audio codec support built in
- Initial FreeBSD support landed along the way

## Notes for Package Maintainers

- The quickshell UI is embedded in the dms binary and mounted at runtime. Packages no longer install `/usr/share/quickshell/dms`, and XDG auto-discovery of `~/.config/quickshell/dms` is removed: `-c` or `DMS_SHELL_DIR` explicitly override the embedded config.
- The build requires a git submodule to be checked out as part of the build process. `git submodule update --init --recursive` should be run before building.
- Release binaries and all -git packages build with the embedded shell.
- The greeter is its own package now, [dank-greeter](https://github.com/AvengeMedia/dank-greeter), with its own release artifacts. `dms greeter install` expects the dms-greeter binary from that package.
- dgop and curl are no longer external dependencies.
- dsearch, dgop, dcal, and dgreeter tag and release together with DMS from this release on.

## Plugins

The plugin ecosystem got numerous updates this cycle

- **New grid-style plugin browser**, and runtime plugins are searchable from settings
- **Portable plugin lockfile** for reproducing a plugin set across machines
- **Support for multiple plugin & theme registries**: `dms registry add <name> <git-url>`, or Settings → Plugins → Registries. Themes resolve from extra registries too
- **Plugin translations**: drop a `translations/` directory next to `plugin.json` and wrap strings in `I18n.trFor("myPlugin", "...")`. Nothing has to land in the DMS repo, users get your translations by installing the plugin
- **Desktop widgets**: Added a runtime resize API. For example, a widget can now change its size in response to user interactions or some internal conditions.
- Plugins are a step in the first-start wizard now, and the launcher's power options moved to a built-in plugin

The [registry](https://plugins.danklinux.com) is past 335 plugins and 42 themes, 86 of the plugins added this cycle. Two standouts:

- **[Quick Capture](https://github.com/hthienloc/dms-quick-capture)** by Loc Huynh: screen capture with drawing and annotation tools, plus OCR and QR decoding
- **[Dank Software Depot](https://github.com/vinceecniv/DankSoftwareDepot)** by Vincent Blok: a full software and updates center - update cards with release notes, an app store covering system repos, Flathub, and AppImage, installed-software management, and firmware updates. Fedora first, Debian/Ubuntu and Arch experimental.

## Translations

DMS ships 21 languages besides English. The term catalog got an overhaul this cycle: around 160 dead terms deleted, context added where one English word was doing two jobs, and a mechanism for carrying the same term under different contexts. Arabic and Ukrainian are new. Time and date formatting can follow the system locale instead of the DMS format options.

Plugins carry their own catalogs on top of that, so a plugin can be translated without anything landing in the DMS repo.

## Everything Else

- **Bluetooth**: multi-adapter support, soft rfkill unblock
- **Notifications**: DnD bypass globally and per-app, an option to ignore app-requested timeouts, and running the default action on body click instead of expanding the text
- **Launcher**: ctrl-tab to cycle modes, a spotlight style for the niri overview, and IPC parity between spotlight-bar and the full launcher
- **Dock**: separate pinned and running apps, cycle grouped windows, minimize support
- **Clipboard**: drop content in to store it, an overlay layer option, and clearing only what the filter matches
- **Bar**: corner style and length padding, a focused window details popout, configurable tray icon spacing, popout variants for the power menu and color picker
- **Lock screen**: vertical clock style, a separate text input for IMEs, an option to hide weather
- **Settings**: Niri keyboard and mouse/touchpad tabs, location search for theme and gamma coordinates
- **Gamma**: configurable transition duration for time-based night mode, values below 2500k, a suspend-aware scheduler that stops losing track across sleep, and gamma and contrast sliders that work with night mode off
- **Power menu**: user-defined custom buttons, soft reboot on systemd
- **Battery**: optionally lower refresh rate on battery, estimated end time, charge and discharge rate in the bar widget
- **Wallpaper**: folder-based selection, shuffle, random cycling order
- **Install**: `dms setup headless` and a non-interactive dankinstall script
- **IPC**: `settings dump` for the full live config as JSON, `dumpSession`, notification dismiss, tray menu open, and `openAt`/`toggleAt` for opening popouts at a location

## What's Next

1.6 is also a direction marker. DMS started as a shell, and the pieces around it - search, monitoring, calendar, greeter - have grown into a suite that now versions and releases as one. From here development shifts toward a full desktop environment paradigm: standalone apps that share the Dank design language and theming, on any compositor, instead of everything living inside the shell.

In development for upcoming releases:

- **Standalone file browser**: the file browser graduates from a shell surface into its own app
- **DankConnect**: phone integration for the Dank Desktop
- More shell built-ins splitting into standalone suite apps, the way the greeter did this cycle
